# Evoluta_frontend — a Mesa de Trabalho Evoluta, com todas as regras

Índice: **A** Visão · **B** Montagem passo a passo · **C** Regras numeradas (R-USR, R-TOK, R-MOL, R-ENT, R-TEL, R-EST, R-TXT, R-ACE, R-RES, R-IMP, R-PREF, R-ROT, R-AUTH, R-MARCA, R-GEN, R-SIT, R-DOC, R-DOM, R-HOOK, R-VER) · **D** Armadilhas aprendidas · **E** Checklist e relato · **F** Limites conhecidos · **G** Mapa de arquivos.

## A. Visão e quando usar

Todo sistema da Evoluta parece **uma mesa de trabalho de repartição**: moldura azul-noite em volta e, dentro, **folhas de papel marfim** com pastas, carimbos, calendário de parede, bloco de espiral e bilhete autoadesivo. O sistema de referência é o **LicitarsAI**; esta skill guarda cópia fiel e **corrigida** de tudo que o define.

- **Requisito central: "exatamente os mesmos elementos".** Não reinterprete: copie `assets/` e troque só o que a tabela de adaptação (`references/08`) manda trocar (nome, logo, itens do menu, textos do domínio).
- **Quando usar:** sistema novo da Evoluta; sistema existente que deve ganhar o visual; revisão de tela "no estilo Evoluta"; troca de domínio (de licitação para outro objeto).
- **Onde está cada coisa:** esta página = regras e passos. Detalhe de código e receitas = `assets/` e `references/` (mapa na seção G). Na dúvida entre texto e código, **vale o código/CSS** de `assets/`; entre a skill e os `exemplos/` (cópias do LicitarsAI), **vale a skill** (`references/11`).
- **Autossuficiência:** com esta skill e os arquivos de `assets/` não é preciso nenhuma outra informação para construir o front end completo.

## B. Montagem passo a passo (sistema novo)

Use uma **pasta nova e vazia** para o projeto (copiar `assets/base/` por cima de pasta com trabalho sobrescreve arquivos). Em projeto que **já existe**, não copie `assets/base/`: siga `references/08`, passos "2. Passos" e "3. O que trocar".

**B0 — Antes de começar.** Descubra a stack e as regras do repositório (CLAUDE.md, arquivos protegidos, hooks) e obedeça-as (R-HOOK). Não faça commit nem publique nada sem o usuário pedir. A stack assumida: React + Vite + TypeScript + Tailwind **v3** (`darkMode: ["class"]`) + shadcn/Radix + lucide-react + react-router; Node 18.18+ (20 e 24 testados). Outra stack: mantenha **CSS, tokens, medidas e estrutura HTML** idênticos e reescreva só a cola do framework.

**B1 — Copiar o projeto-base** (da pasta desta skill para a pasta nova; `<SKILL>` = `C:\Users\<usuario>\.claude\skills\Evoluta_frontend`):

1. Conteúdo de `<SKILL>/assets/base/` → raiz do projeto (renomeie `gitignore.txt` para `.gitignore`; **não** copie o `LEIA-ME.md`).
2. `<SKILL>/assets/styles/index.css` → `src/index.css`.
3. `<SKILL>/assets/tailwind.config.ts` → `tailwind.config.ts` (traz o `safelist` por nomes explícitos).
4. `<SKILL>/assets/public/*` → `public/`.
5. `<SKILL>/assets/components/{layout,mesa,auth}` → `src/components/{layout,mesa,auth}`. O mapa arquivo→destino completo está em `assets/base/LEIA-ME.md`.
6. Cópia em massa no Git Bash, se o ambiente permitir: `cp -r "<SKILL>/assets/base/." .` (depois `mv gitignore.txt .gitignore` e apague o `LEIA-ME.md` copiado), `cp <SKILL>/assets/styles/index.css src/index.css` etc. Se um hook recusar o comando, **não burle** (R-HOOK-01): copie com Read + Write ou peça ao usuário para rodar.

**B2 — Compilar a base pura:** `npm install` e `npm run build` (o script `build` já roda `tsc --noEmit` e depois `vite build`; só o `typecheck` é `npm run typecheck`). Use `tsc --noEmit` (`tsc -b` deixa um `tsconfig.tsbuildinfo`). Esperado: `rc=0`, sem aviso de chunk, JS ≈ 465 kB e CSS ≈ 121 kB (medido na cópia de prova desta skill: 464,64 kB e 121,37 kB). Abrir o sistema: `npm run dev` (porta 8080, o Vite usa a seguinte se ocupada); com várias instâncias: `npx vite --port 8301 --strictPort`. Primeira carga em branco quase sempre é import faltando: console + `npx tsc --noEmit`. `npm install` avisa do `postinstall` do esbuild e do `npm audit`: o build funciona; **não** rode `npm audit fix --force`.

**B3 — Trocar a marca** (R-MARCA): edite `src/config/marca.ts` (nome, logo, frases, objeto, campos, ação principal, destinos do celular, prefixo de armazenamento) e, **fora do `MARCA`**: `name` do `package.json`, `<title>` do `index.html` (marcado "TROCAR"), o logo (`public/logo-<sistema>.svg` + `MARCA.logo`) e a chave de tema do script anti-flash do `index.html`.

**B4 — Trocar o menu e as rotas** (R-ROT): `components/layout/navegacao.ts` (grupos, itens, ícones lucide, perfis) e `App.tsx`; rota nova = tela nova ou `EmConstrucao`.

**B5 — Trocar o domínio** (R-DOM, R-SIT, R-GEN): situações, fases, divisórias, agenda, textos, `genero` do objeto. Rode as **quatro buscas** de textos herdados (R-DOM-05).

**B6 — Construir cada tela** com a casca certa (R-TEL-01) seguindo a receita em `references/09`, os textos de `references/10` e os modelos que compilam em `assets/base/src/pages/`.

**B7 — Verificar** (R-VER): build, checklist `references/07` nos **dois temas** e a ~400px, e os formatos de relato (seção E). Não marque "conferido" o que não olhou.

## C. Regras numeradas

> Cada regra: **ID — enunciado — valor/arquivo**. Os valores exatos (HSL, hex, classes, arquivos) são os de `assets/`. "Fonte": o detalhe fica em `references/NN`.

### R-USR — Quem é o usuário e como responder

- **R-USR-01** — O usuário costuma **não programar**: responda em **português do Brasil**, descreva o **efeito na tela** ("o menu agora fica azul e recolhe"), nunca a implementação.
- **R-USR-02** — Diga sempre o que ficou **pela metade, o que é simulado e o que não foi possível testar**; ele aprova pelo que vê e não pergunta pelo que você não contou.
- **R-USR-03** — **Nunca peça print/captura de tela** do sistema (traz dado real). Leia o código.
- **R-USR-04** — **Nunca copie dado real** de órgão público (nomes, processos, valores, CPF/CNPJ) para código, fixture, doc ou PR. Dado de exemplo é **inventado**; documento formatado usa placeholder inválido (`000.000.000-00`, `11.111.111/1111-11`).
- **R-USR-05** — Nomes de tela **rejeitados** pelo usuário, que não devem voltar: "Planta da repartição", "Livro da gestão", "Entregar minha mesa". Aprovados: "Quem está com o quê", "Processos do período". Rejeitado também: barras de menu douradas/bege (o menu é azul; o ouro é detalhe). Prefira nomes que a pessoa entenda sem treinamento.
- **R-USR-06** — Feche cada passo com **um** próximo passo; nunca mande abrir chamado na TI do órgão por problema do ambiente (é com a equipe do produto).

### R-TOK — Cores, tipografia, raios, sombras (fonte: `references/01`, `assets/styles/index.css`)

- **R-TOK-01** — **Cor só por token** (`bg-background`, `text-muted-foreground`, `bg-moldura`, `bg-[hsl(var(--cta))]`…). Nunca hex nem `gray-*`/`slate-*` (some no tema escuro; no grep use `\bslate-`, que evita o falso positivo de `translate-`). Exceções conhecidas: `text-white` do botão `--cta`, sombras/véus `rgba`/`bg-black/80`, os dois hex do `<style>` anti-flash do `index.html` (`#F8F5EE` claro, `#141A2A` escuro) e as cores cruas herdadas do shadcn em `ui/` (toast, dialog, sheet, alert-dialog, select).
- **R-TOK-02** — Tokens são **canais HSL crus** (`42 42% 95%`) usados como `hsl(var(--x))`, com par claro (`:root`) e escuro (`.dark`; tema por classe em `<html>`). Os principais (claro / escuro): `--background` `42 42% 95%` (#F8F5EE) / `224 35% 12%` (#141A2A); `--foreground` `226 38% 16%` / `40 10% 96%`; `--card` `0 0% 100%` / `224 33% 16%`; `--primary` `220 50% 28%` / `211 47% 45%`; `--secondary` `217 49% 35%` / `225 28% 28%`; `--muted-foreground` `224 17% 43%` / `222 20% 70%`; `--border` `41 22% 81%` / `227 30% 24%`; `--moldura` `227 42% 19%` (#1C2545) / `227 44% 8%` (#0B0F1C); `--moldura-2` `225 43% 24%` / `225 36% 15%`; `--gold` `39 44% 51%` (#B8924A, igual nos dois); `--cta` `211 45% 45%` (#3F72A8, igual nos dois). Tailwind: `bg-moldura`, `bg-moldura-2`, `text-moldura-foreground` (aceitam `/opacidade`), `text-gold`, `bg-gold`.
- **R-TOK-03** — **`--accent`/`--ring`/`--sidebar-ring` do claro = `210 42% 46%` (#4475A7)**, não o 50% do original: texto branco sobre ele mede **4,83:1** (AA). Escuro: `210 55% 62%` (#6A9DD0) e `--accent-foreground` escuro `227 44% 8%` (texto **escuro** sobre o realce no escuro). `--color-accent-light` espelha: `#4475A7` / `#6a9dd0`.
- **R-TOK-04** — **`--input`** (borda de campo, botão secundário, trilha do interruptor desligado) é **mais escuro que `--border`** por WCAG 1.4.11 (componente ≥ 3:1): claro `224 13% 54%` (#7A8399: 3,46:1 sobre o marfim, 3,79:1 sobre o branco); escuro `222 16% 46%` (#636E88: 3,40:1 sobre o fundo, 3,07:1 sobre o card); alto contraste `224 25% 45%` / `222 20% 70%`. O `--border` (fio de papel) continua suave de propósito e **não** serve de borda de campo.
- **R-TOK-05** — **Quatro fontes, cada uma com seu papel; nenhuma quinta:** `font-sans` Plus Jakarta Sans 300/400/500/600/700 (corpo); `font-display`/`font-serif` Cormorant Garamond 500/600/700 (títulos, saudação, **texto de documento**); `font-ui` Barlow Semi Condensed 500/600/700 (rótulos em caixa-alta, carimbos, títulos de grupo do menu); `font-mono` IBM Plex Mono 400/500 (números de processo, códigos, protocolo, hora). Pacotes `@fontsource/*` servidos pelo próprio sistema (não por CDN), importados **antes** de `index.css` (o `index.css` já importa o 300 da Jakarta e o 700 da Barlow; copiando `index.css` + `main.tsx` da base todos os pesos carregam). As variáveis `--font-body/-display/-ui/-mono` **precisam existir** (o CSS da mesa as usa).
- **R-TOK-06** — **Números grandes em Cormorant** levam `lining-nums tabular-nums` na própria linha (sem isso o "1" parece "I" e o "6" desce). Não existe `.numero-grande`. `h1–h4` já saem `lining-nums` por regra global.
- **R-TOK-07** — Padrões de texto: título de tela `font-display text-4xl md:text-[2.75rem] font-semibold leading-[1.08]` (`FolhaDaTela`; Minha Mesa `md:text-5xl leading-none`); seção `font-display text-2xl font-semibold`; rótulo/legenda `font-ui text-xs font-semibold uppercase tracking-[0.12em] text-muted-foreground`; cabeçalho de tabela `font-ui text-xs font-semibold uppercase tracking-[0.1em] text-muted-foreground` (o `ui/table.tsx` da base já traz; em outro projeto copie); número/código/hora/data de tabela `font-mono`; documento oficial `.documento-oficial`/`.texto-do-documento`.
- **R-TOK-08** — **Ouro (`--gold`) só como preenchimento, ícone, divisão, foco ou selo sobre azul-noite.** Nunca texto ou borda de ouro sobre marfim (2,61:1 reprova). No escuro serve também sobre a folha escura. Borda de aviso no claro usa o ocre de aviso (`--color-status-warning`), não ouro.
- **R-TOK-09** — **Azul de ação `--cta`:** o botão que "faz o trabalho" (gerar; **um por região**) e a ação "Nova …" do menu e da barra do celular = `bg-[hsl(var(--cta))] text-white hover:brightness-90` **ou** `<Button variant="cta">` (equivalente; existe em `ui/button.tsx` da base: em outro projeto confira, pois variante inexistente compila e não faz nada). **O hover tem que escurecer** (`brightness-90`, 5,99:1); **nunca** `hover:bg-[hsl(var(--cta)/0.9)]` (clareia: ~4,24:1, reprova AA). Texto branco sobre `--cta` em repouso: 5,09:1. Botão comum da folha (Salvar, Criar, Entrar) = `<Button>` padrão (`bg-primary`, outro azul). Nunca botão de ouro. Tamanhos: `default h-10 px-4`, `sm h-9 px-3`, `lg h-11 px-8`, `icon h-10 w-10`.
- **R-TOK-10** — Link/ação em texto sobre a folha: `text-primary dark:text-accent` (`font-semibold hover:underline`, com "›" no fim quando leva a outra tela). Texto branco sobre `--primary` escuro: 5,08:1.
- **R-TOK-11** — Raios: `--radius` 0.5rem (`lg` 8px, `md` 6px, `sm` 4px); folha da moldura `rounded-t-xl` do tablet para cima (cantos de baixo retos). `.folha` raios 4/10/10/10 com sombras sobrepostas. Sombra da folha principal sobre o azul `shadow-[0_24px_48px_-24px_rgb(0_0_0/0.55)]`; cartão de entrada `shadow-[0_24px_48px_-32px_rgb(0_0_0/0.45)]`. **A sombra da `.folha` é sutil por desenho**: `0 18px 40px -24px hsl(var(--mesa-sombra) / 0.55)`; não "melhore" a geometria (fidelidade ao original) e **nunca** use `--mesa-noite` nela (é a cor do fundo; a sombra sumia).
- **R-TOK-12** — **`.mesa-faixa` é o cabeçalho da ferramenta** dentro da folha (`MesaPagina`): **marfim** no claro e **ardósia escura** no escuro (`--mesa-noite` = 42 42% 95% / 224 35% 12%). **Não é** a faixa azul-noite do alto (`--moldura`, `AppHeaderV3`). Não troque uma pela outra.
- **R-TOK-13** — **Tintas dos carimbos** (`--tinta-azul` 232 51% 42%, `-verde` 150 55% 27%, `-carmim` 354 66% 38%, `-ocre` 36 77% 31%, `-violeta` 268 43% 44%; escuro: azul 234 83% 83%, verde 145 47% 68%, carmim 354 76% 78%, ocre 40 72% 67%, violeta 266 69% 81%; grafite = `--mesa-texto2`). As classes `.tinta-*` ficam **FORA** do `@layer` no `index.css` (o Tailwind descartaria `tinta-${tinta}` montada em runtime); **não as mova para dentro de um `@layer`**. `.borda-tinta-ocre/-carmim` ficam dentro de `@layer components` e por isso estão no `safelist`.
- **R-TOK-14** — **`safelist` do `tailwind.config.ts` por nomes explícitos** (cerca de 56 nomes, todos presentes no CSS gerado; não regex, que gerava avisos e não casa com `@layer components`): sem ele o build de produção remove `.bilhete`, `.ficha`, `.folhinha`, `.bloco-espiral`… **Classe nova em `@layer components` entra na lista.** Rode `vite build` e confira as classes no CSS gerado (não só o `dev`).
- **R-TOK-15** — **Legado, não usar em tela nova:** `navy-*`, `platinum-*` (invertida por tema), `steel-*`, `--color-*`, `--main-bg`/alias antigos, `.glass-*`/`.glass-card` (hoje folha sólida), `card-dashboard`, `chat8-*`. O grupo `licitars-*` foi **removido** do `tailwind.config.ts`. O trecho de `index.css` do legado (≈ linhas 363–711) não vai para sistema novo, salvo se uma tela copiada o use. Legenda de gráfico: `text-foreground`/`text-muted-foreground`, nunca `text-platinum-*`.
- **R-TOK-16** — **Espaçamento em múltiplos de 4.** Meios passos de 2px (`0.5`, `1.5`, `2.5`) só no ajuste fino de rótulos/itens pequenos, nos arquivos que já os têm (moldura: `py-2.5` e `space-y-0.5` no `AppHeaderV3`/`AppSidebarV3`, `px-1.5` na `BuscaRapida`; peças `CalendarioDeMesa`, `PastaDoProcesso`, `PastaNaGaveta`, `Mesa`, `DivisoriasDeFiltro`, `ConfirmarAto`, `ResumoDaPasta`, `Acessibilidade`; `index.css` legado). Em tela nova: layout só em múltiplos de 4. Para achar: Grep `\b(py|px|gap|p|m|mt|mb|mx|my|space-y)-(0\.5|1\.5|2\.5|3\.5)\b`.
- **R-TOK-17** — **Larguras de conteúdo:** `max-w-7xl` em `FolhaDaTela`; `max-w-[1400px]` em `MesaPagina`; páginas de texto `max-w-5xl` (preferências, documento) ou `max-w-6xl` (ajuda, formulário).
- **R-TOK-18** — **Medir contraste, não confiar no olho.** Fórmula WCAG: `L = 0,2126·R + 0,7152·G + 0,0722·B` (canal linearizado: `c/255 ≤ 0,03928 ? c/255/12,92 : ((c/255+0,055)/1,055)^2,4`); razão `(L1+0,05)/(L2+0,05)`. Mínimos AA: 4,5:1 texto normal, 3:1 texto grande (≥ 24px, ou ≥ 18,66px em negrito) e ícones/bordas de interface. Meça contra os **fundos reais** (marfim, `--moldura`, papel, folha escura). Script de console em `references/01` ("Como medir contraste"); sobre gradiente ou imagem, meça à mão.

### R-MOL — Moldura, menu, folha, celular (fonte: `references/02`, `03`, `04`)

- **R-MOL-01** — **Casca (`AppLayoutV3`)**: contêiner `flex h-screen (h-dvh) w-full flex-col overflow-hidden bg-moldura` + `env(safe-area-inset-*)`; 1º filho o link "Pular para o conteúdo" (`sr-only`, no foco vira botão fixo com `focus:ring-2 focus:ring-gold`); depois `AppHeaderV3`; então `div.flex.min-h-0.flex-1` com `AppSidebarV3` + `main#conteudo`; por último `BarraDoCelular` (só celular). Telas (`<Outlet/>`) ficam dentro dela; login e recuperação ficam fora (R-ENT).
- **R-MOL-02** — **Faixa do alto (`AppHeaderV3`)**: `flex items-center gap-3 bg-moldura px-4 py-2 text-moldura-foreground md:gap-5 md:px-6` e, nesta ordem: (1) hambúrguer (`md:hidden`); (2) botão recolher/expandir menu (≥ md, `PanelLeftClose/Open`, `aria-expanded`, `aria-controls="menu-lateral"`); (3) **logo do produto** (`h-9 sm:h-12 md:h-14`, `w-auto`, `-my-1`; link para o início; `alt` "Produto — ir para <início>"; encolhe com `object-contain object-left` quando a faixa aperta); (4) divisor `h-8 w-px bg-moldura-foreground/20` (≥ sm); (5) `AssinaturaEvoluta` `w-[5.5rem] text-moldura-foreground/70`; (6) selo opcional de perfil especial; (7) direita `ml-auto flex gap-1 md:gap-2`: `BuscaRapida` · tema · Ajuda (`HelpCircle`; ambos ≥ sm) · divisor · avatar.
- **R-MOL-03** — **Avatar** `h-9 w-9` círculo `bg-moldura-foreground/15` com a inicial em `font-bold`, **sem borda dourada**; ao lado (só ≥ lg, `max-w-[9rem] xl:max-w-[14rem]`, `truncate`, para "Bem maior" não expulsar o avatar) nome (`font-semibold`) e **perfil legível** (`NOME_DO_PERFIL`, primeira letra maiúscula; `text-xs text-moldura-foreground/65`). Botão da conta com `aria-label="Conta de {nome}: abrir menu"`; abre menu com nome, e-mail, Sair e a versão ("Produto vX.Y.Z-sha").
- **R-MOL-04** — **Foco na faixa:** todos os botões de ícone usam `BOTAO_NA_FAIXA` = `text-moldura-foreground/80 hover:bg-moldura-foreground/10 hover:text-moldura-foreground focus-visible:ring-2 focus-visible:ring-gold focus-visible:ring-offset-0` (hambúrguer, recolher, tema, Ajuda, busca, conta e "pular" iguais; nada de `ring-ring` com offset marfim).
- **R-MOL-05** — **Menu lateral (`AppSidebarV3`)**: `nav#menu-lateral hidden md:flex bg-moldura px-3 pb-4 pt-2 gap-5 overflow-y-auto` + `.rolagem-moldura`; largura `w-64` aberto / `w-[4.25rem]` recolhido (`transition-[width] duration-200`, sem animação em `motion-reduce`). **Primeiro item = ação principal** ("Nova …") `bg-[hsl(var(--cta))] text-white font-semibold rounded-lg` (recolhido: quadrado 40×40 com `Plus` e tooltip). **Grupos**: título `font-ui text-[11px] uppercase tracking-[0.14em] text-moldura-foreground/50` (recolhido: traço `h-px w-6 bg-moldura-foreground/20`), lista `space-y-0.5`. **Item**: `rounded-lg text-sm px-3 py-2.5 gap-3`, ícone `h-[1.125rem] w-[1.125rem]`; inativo `text-moldura-foreground/75 hover:bg-moldura-foreground/10`; **ativo** `bg-moldura-2 font-semibold text-moldura-foreground` + barrinha azul 4px à esquerda (`before:w-1 before:bg-accent`) + `aria-current="page"`. **Pé** (`mt-auto border-t border-moldura-foreground/10 pt-3`): itens da pessoa (Acessibilidade). Recolhido: nome em `sr-only` + `Tooltip` à direita. Estado aberto/recolhido em `localStorage` (`chaveDoSistema("menu-lateral")`, hook `useMenuLateral`), podendo vir de preferência "começar recolhido".
- **R-MOL-06** — **Estrutura do menu (vale para todo sistema):** ação principal no alto → **grupos** com título em caixa-alta (Trabalho → Consulta → <unidade> → Administração) → **pé** (Acessibilidade). Itens por perfil (`perfis?`); grupo vazio some. - Impressão real (papel/PDF) e a animação do carimbo quadro a quadro não foram medidas (só CSS e emulação `@media print`); 400px foi conferido por iframe de mesmo domínio, não em aparelho real; Tab real e o .docx aberto no Word não foram conferidos; a captura de tela com o filtro SVG do carimbo grande chegou a travar no emulador (não confirmado como defeito).
- O **logo oficial** de cada produto precisa ser fornecido (há modelo SVG); **lint e testes** não vêm na base; `npm audit` com 9 avisos (R-VER-02).
- Itens que exigem **editar arquivo** ao trocar de domínio: R-DOM-08. `blocosParaMarkdown` não escapa markdown. Documento com id de item inexistente mostra demonstração (R-DOC-04). A base **não** traz modelo de aba para divisória nova nem store real de dados (armazém em memória). A receita da Agenda em 09 é mais completa que a base (versão enxuta). Cerca de 17 detalhes de redação apontados na última auditoria ficaram sem correção de propósito (não afetam o uso).
- `exemplos/` não compilam sozinhos (14 imports sem arquivo, listados no `LEIA-ME` deles) e trazem coisas do original que **não** se copiam (`references/11 §2`).
